Both images use the same blue and white visual style, a white background and readable sans-serif labels. SVG sources are authoritative. The [diagram manifest](manifest.json) records generation time, browser and renderer versions, dimensions, and SHA-256 hashes of each SVG and PNG.

Privacy Protocol defines the rules that make a private operation valid. Privacy Core implements those rules and their cryptographic machinery. The Privacy SDK exposes these capabilities to application developers. The host owns its CCC Client, wallet and operation-scoped Signer, supplying CCC capabilities to the SDK through an explicit adapter boundary.

The overview shows the reference application consuming the SDK alongside the host's injected CCC capabilities. The SDK exposes Core/Protocol rules, whose CKB scripts settle through Scripts and Cells. CCC is an application-owned capability, not a privacy layer beneath the Core.

Figure 6 shows the Client supplied at initialization, the Signer supplied per operation, and privacy operations/verified state returned to the host. The SDK does not own React, wallet connectors or raw private keys. Target capability descriptions do not establish that production adapters or live settlement are available today.

The reference application is the first controlled consumer of the SDK. Its fixed-denomination privacy pool validates commitments, Merkle state, nullifiers, proof authorization, CT conservation and CKB state transitions; it does not define the architectural boundary or introduce a separate commercial wallet product.

## Reproduce the exports

With the repository dependencies installed, run from the repository root:

```sh
node frontend/scripts/export-architecture-diagrams.mjs
```

The renderer uses Playwright and tries installed Chrome, bundled Chromium, then Edge. Set `PLAYWRIGHT_CHANNEL` to select one channel explicitly. If no browser is installed, run `pnpm --filter frontend exec playwright install chromium` and repeat the command.

The renderer blocks external resources, removes browser page margins, checks label bounds and page overflow, and exports at exactly 1600 pixels wide with device scale factor 1. It records the resulting hashes in `manifest.json`. Font availability or browser updates can change pixels; the recorded browser and hashes identify this export. Inspect both PNGs after changing the SVGs. Do not hand-edit exported PNGs or remove their target-architecture labels.

The local proposal generator validates these reviewed SVG/PNG hashes and preserves the exports instead of replacing them with its older raster drawing functions. No Word rebuild is required to regenerate these two diagrams.
